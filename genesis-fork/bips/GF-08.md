# GF-08: Block validity — time, size, structure

| Field | Value |
|-------|-------|
| BIP | GF-08 |
| Title | Block validity: time, size, structure |
| Author | Travis Dale Jones |
| Status | Active |
| Created | 2026-09-21 |

## Abstract

Structural block rules: strictly increasing timestamps bounded by
network time + 2 hours, 1,000,000-byte maximum block size, exact
prev-hash linkage, and merkle-root commitment over display-order txids.

## Motivation

The minimal structural envelope that keeps the chain ordered,
bounded, and tamper-evident — without Bitcoin's median-time-past
machinery, which v1 defers.

## Specification

A block at height `h` with previous block `prev` is structurally valid
iff ALL hold:

1. `block.prev == prev.hash` (32-byte hash linkage; for height 1, the
   genesis hash from GF-02).
2. `block.time > prev.time` (strictly increasing; no median-time-past
   in v1).
3. `block.time <= network_time + 7200` (no more than 2 hours in the
   future; violation: `"time too far in future"`).
4. `block.bits == required_bits(h, …)` (see GF-03; testnet min-difficulty
   exceptions per GF-09).
5. `int.from_bytes(sha256d(header), "big") <= bits_to_target(bits)`
   (PoW; see GF-03).
6. Serialized block ≤ 1,000,000 bytes (`"oversize"` otherwise).
7. At least one transaction (the coinbase); empty blocks invalid.
8. `merkle_root ==` computed root over txids, where each txid is
   `sha256d(tx)` reversed to display order and each parent level is
   likewise reversed (persisted v1 convention — byte-exact with blocks
   1–5).
9. Coinbase passes GF-04 (lineage) and pays `subsidy + fees` (GF-06);
   with non-coinbase transactions present, GF-07's full tx validation
   applies.

## Rationale

Strictly-increasing time (instead of MTP) is simpler to implement and
audit on a young chain; the 2-hour future bound is Bitcoin's own
rule. The 1 MB cap matches Bitcoin's original block size.

## Reference implementation

`genesis_fork.py`: `validate_block()` returns the list of violations
(empty = valid); `ser_header()`, `merkle_root()`.

## Test vectors

- Mainnet blocks 1–5 satisfy all nine rules (verified by revalidation).
- A block with `time <= prev.time` is rejected (`"time not increasing"`);
  a block stamped >2 h ahead is rejected (`"time too far in future"`).
