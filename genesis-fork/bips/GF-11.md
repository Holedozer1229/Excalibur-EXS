# GF-11 — Post-Quantum Transaction Authorization (ML-DSA-65 Hard Fork)

## Summary

GF-11 is a consensus hard fork that replaces secp256k1/ECDSA transaction
authorization with ML-DSA-65 (FIPS 204, Dilithium mode 3) for all outputs
created at or after the activation height. Every persisted pre-activation
block and every pre-activation consensus rule is preserved byte-for-byte.

## Motivation

Shor's algorithm breaks secp256k1/ECDSA once a public key is exposed.
ML-DSA-65 is a NIST-standardized post-quantum signature scheme. This fork
moves new coin authorization to ML-DSA-65 while keeping legacy UTXOs
spendable indefinitely so no funds are frozen.

Honest scope:

- ML-DSA addresses signature authorization only. SHA-256d retains roughly
  128-bit generic security against idealized Grover search; mining is not
  claimed "quantum-proof".
- The pure-Python ML-DSA implementation (`mldsa.py`) is not certified,
  audited, constant-time, or production-hardened. It is bit-for-bit
  interoperable with the pq-crystals/dilithium C reference (mode 3).
- Existing `OP_TRUE` coinbases are insecure; post-activation rewards require
  a deliberate PQ output.

## Activation

- Activation height: **10,000** (mainnet and testnet).
- `gf11_active(height)` is true iff `height >= 10000`.
- The live chain was at height 12 when this height was selected; activation
  is far in the future and no persisted block is affected.

## PQ output format

A PQ output scriptPubKey is exactly 1,954 bytes:

```
PQ_SPK_PREFIX = 0x00 0x11
scriptPubKey  = PQ_SPK_PREFIX || pk        (pk = 1,952-byte ML-DSA-65 public key)
```

It is matched structurally, never executed by the legacy script evaluator.

## PQ input format

An input spending a PQ output carries exactly 3,310 bytes in scriptSig:

```
scriptSig = 0x11 || sig                    (sig = 3,309-byte ML-DSA-65 signature)
```

The public key is taken from the output being spent, not from the input.

## PQ signature digest (exact)

For input `in_idx` spending PQ scriptPubKey `script_code`:

```
sighash     = sighash_all(t, in_idx, script_code)   # legacy SIGHASH_ALL preimage hash
pq_msg      = b"EXCAL-GF11-PQ-SIGHASH\x00" || LE32(in_idx) || sighash
pq_digest   = sha256d(pq_msg)
verify(pk, pq_digest, sig) must be true             # ML-DSA-65
```

Domain separation is fixed and empty-context pure ML-DSA (`00 00`) is used
inside `mldsa.py`, matching the KAT vectors.

## Transaction versions

- Pre-activation: only version 1; any PQ output or PQ scriptSig is rejected
  as non-standard.
- Post-activation: version 1 or 2.
  - Version 2 is REQUIRED if any input spends a PQ output.
  - Version 2 is allowed only at/after activation.
  - Version 1 may spend legacy inputs and create PQ outputs (migration), but
    must not spend PQ outputs.

## Output rules

- Pre-activation: outputs must be P2PK or `OP_TRUE` (unchanged v1 rules).
- Post-activation, every output of every non-coinbase transaction must be a
  PQ output. New P2PK and new `OP_TRUE` outputs are rejected.
- Legacy UTXOs created before activation remain spendable indefinitely
  (subject to the 100-block coinbase maturity rule). They stay
  quantum-vulnerable until their owners migrate them to PQ outputs.

## Coinbase policy

- Pre-activation: coinbase pays to `OP_TRUE` (unchanged).
- Post-activation: every coinbase output must be a PQ output. A miner without
  a configured ML-DSA-65 public key cannot produce a valid post-activation
  block; this is deliberate.
- Coinbase value rule is unchanged: `coinbase_value == subsidy + fees`.
- Coinbase-output enforcement runs even for coinbase-only blocks.

## Limits (consensus)

- `PQ_SIG_LEN = 3309`, `PQ_PK_LEN = 1952`.
- Maximum 64 PQ signature verifications per block (post-activation).
- Maximum block size remains 1,000,000 bytes; mempool policy keeps the
  100,000-byte per-transaction cap.

## Failure behavior

| Condition | Result |
|---|---|
| PQ output/input before activation | rejected: non-standard |
| Version 2 before activation | rejected: version != 1 |
| PQ spend in version-1 tx (post-activation) | rejected |
| New P2PK/`OP_TRUE` output at/after activation | rejected |
| Wrong scriptSig length or version byte | rejected: malformed PQ scriptSig |
| ML-DSA verify false | rejected: script failed |
| pq_digest mismatch (replay/wrong input index) | rejected: script failed |
| >64 PQ verifications in a block | rejected |
| Post-activation coinbase not PQ | rejected |

## What this fork does not change

- Genesis block, PoW, retargeting, subsidy schedule, 1 MB block cap,
  coinbase lineage rule (first push = LE(bits)), txid computation, and all
  pre-activation validation are untouched.
- `test_v1_characterization.py` must keep passing unchanged: it pins the
  historical behavior.
