# GF-09: Testnet min-difficulty rule

| Field | Value |
|-------|-------|
| BIP | GF-09 |
| Title | Testnet min-difficulty rule |
| Author | Travis Dale Jones |
| Status | Active |
| Created | 2026-09-21 |

## Abstract

Testnet-only rule, mirroring Bitcoin's testnet: if `2 × 600 s` (1200 s)
pass with no block, a block may use minimum difficulty (`init_bits`,
target 2²⁴⁰) regardless of the retarget schedule. Min-difficulty blocks
do not move the retarget anchor.

## Motivation

Testnets have sporadic hashrate; without relief, the chain can stall for
hours after miners leave. The rule keeps the testnet usable while
leaving mainnet's difficulty schedule strict.

## Specification

1. Applies to testnet only (`min_diff_rule == True`); mainnet never
   uses it.
2. For height `h ≥ 1` with candidate time `t`: if
   `t > time[h-1] + 1200`, `required_bits(h) = init_bits` (`0x1f010000`).
3. When computing a later retarget, the anchor walks back past any
   min-difficulty blocks to the last real-difficulty block (Bitcoin's
   rule): min-difficulty blocks do not dilute the measured timespan.

## Rationale

Byte-for-byte Bitcoin's testnet3 behavior, ported to the fork's
parameters. Mainnet deliberately omits it: real value needs real
difficulty.

## Reference implementation

`genesis_fork.py`: `required_bits()` — the `min_diff_rule` branch at
the top and the anchor walk-back in the retarget computation.

## Test vectors

- `PARAMS["testnet"]["min_diff_rule"] is True`;
  `PARAMS["mainnet"]["min_diff_rule"] is False`.
- A testnet block with `time > prev.time + 1200` validates at bits
  `0x1f010000`.
