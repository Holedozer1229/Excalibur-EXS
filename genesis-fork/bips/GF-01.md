# GF-01: Network identity and chain parameters

| Field | Value |
|-------|-------|
| BIP | GF-01 |
| Title | Network identity and chain parameters |
| Author | Travis Dale Jones |
| Status | Active |
| Created | 2026-09-21 |

## Abstract

Defines the two Genesis Fork networks (mainnet, testnet): names, tickers,
P2P magic bytes, ports, bech32 human-readable parts, and legacy address
version bytes. These parameters give the fork its own network identity,
separate from Bitcoin and from each other.

## Motivation

A hard fork needs unambiguous network identity so that nodes, wallets,
and explorers never confuse fork blocks, addresses, or P2P traffic with
Bitcoin's — or with the fork's own testnet.

## Specification

| Parameter | Mainnet | Testnet |
|-----------|---------|---------|
| Network name | Genesis Fork | Genesis Fork Testnet |
| Ticker | GSF | tGSF |
| P2P magic | `0x4753466B` (ASCII `GSFk`) | `0x47534674` (ASCII `GSFt`) |
| P2P port | 18444 | 28444 |
| RPC port | 18445 | 28445 |
| Bech32 HRP | `gsf` | `tgsf` |
| P2PKH version byte | `0x32` | `0x32` |
| P2SH version byte | `0x55` | `0x55` |
| Target block spacing | 600 s | 600 s |
| Max block size | 1,000,000 bytes | 1,000,000 bytes |

A mainnet block is invalid on testnet and vice versa (different required
difficulty at every height; see GF-03 and GF-09).

## Rationale

Magic bytes spell `GSFk` / `GSFt` so fork traffic is recognizable on the
wire and can never handshake with Bitcoin (`0xD9B4BEF9`) peers. Ports
18444/18445 and 28444/28445 avoid collision with Bitcoin (8333/8332),
testnet3 (18333/18332), and regtest. The `0x32`/`0x55` address versions
were chosen to not collide with Bitcoin mainnet (`0x00`/`0x05`).

## Reference implementation

`genesis_fork.py`: `_mkparams()` / `PARAMS` dict. The P2P layer
(`p2p.py`) handshakes with the network magic; `node_rpc.py` binds the
network's RPC port on localhost.

## Test vectors

- `PARAMS["mainnet"]["magic"] == 0x4753466B`
- `PARAMS["testnet"]["p2p_port"] == 28444`, `PARAMS["testnet"]["hrp"] == "tgsf"`
