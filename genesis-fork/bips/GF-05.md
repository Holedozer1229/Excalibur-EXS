# GF-05: Coinbase v2 — height push (BIP34 lesson)

| Field | Value |
|-------|-------|
| BIP | GF-05 |
| Title | Coinbase v2: height push (BIP34 lesson) |
| Author | Travis Dale Jones |
| Status | Active |
| Created | 2026-09-21 |

## Abstract

The v2 coinbase format appends a block-height push to the scriptSig:
`push(LE(bits)) + push(tag) + push(LE(height))`. The first push is still
LE(nBits), so GF-04's lineage rule holds unchanged; the height push
gives every new coinbase a unique txid.

## Motivation

Bitcoin learned this lesson as BIP34: without a height push, coinbases
from different blocks can be byte-identical and share a txid. The fork
hit this in practice — pre-v2 coinbases were byte-identical within a
(bits, tag) era, so 731 coinbase txids collided in a naive txid-keyed
UTXO set (only 4 distinct entries). The height push fixes it at the
source.

## Specification

1. v2 coinbase scriptSig = `push(LE(bits)) + push(tag) + push(LE(height))`,
   where `height` is the block height as a 4-byte little-endian integer.
2. The lineage rule (GF-04) is evaluated on the first push only and is
   unaffected.
3. Coinbase value = `subsidy(height) + fees` (see GF-06, GF-07).
4. Node UTXO handling disambiguates any pre-v2 duplicate coinbase txids
   oldest-first (historical migration, not a consensus rule for new
   blocks).

## Rationale

Four bytes per block buys globally unique coinbase txids forever, and
keeping LE(bits) first preserves the lineage construction without
exception or version flag.

## Reference implementation

`txscript.py`: `make_coinbase_v2()`; `excal.py`: `mine_one()` builds the
v2 coinbase with the block's fees.

## Test vectors

Mainnet block 1 coinbase scriptSig ends with `04 01000000` = LE(1)
(see the full hex in GF-04). Block 5 (first block mined after the
v2-era restart) carries LE(5).
