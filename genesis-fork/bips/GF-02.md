# GF-02: Genesis anchor — byte-identical Bitcoin genesis

| Field | Value |
|-------|-------|
| BIP | GF-02 |
| Title | Genesis anchor: byte-identical Bitcoin genesis |
| Author | Travis Dale Jones |
| Status | Active |
| Created | 2026-09-21 |

## Abstract

The Genesis Fork shares exactly one block with Bitcoin: the genesis
block. Its 80-byte header is byte-identical to Satoshi's genesis and the
reference implementation recomputes the genesis hash from the header
fields at startup rather than trusting a constant.

## Motivation

Anchoring to Bitcoin's genesis gives the fork a verifiable, famous
starting point — "Bitcoin's history, restarted" — without sharing any
spendable history (see GF-10).

## Specification

The genesis header fields, as encoded in the reference implementation:

| Field | Value |
|-------|-------|
| version | 1 |
| prev | 32 zero bytes |
| merkle root | `4a5e1e4baab89f3a32518a88c31bc87f618f76673e2cc77ab2127b7afdeda33b` (display order) |
| time | 1231006505 (2009-01-03 18:15:05 UTC) |
| bits | `0x1d00ffff` |
| nonce | 2083236893 |

Genesis block hash (display order):
`000000000019d6689c085ae165831e934ff763ae46a2a6c172b3f1b60a8ce26f`

Both networks (mainnet and testnet) share this genesis block. The fork
diverges from block 1 onward.

## Rationale

Recomputing the hash from header fields (`verify_genesis()`) instead of
hard-coding the hash string means the anchor is *verified*, not trusted:
any transcription error in the header fields fails loudly at startup.

## Reference implementation

`genesis_fork.py`: `GENESIS` dict, `verify_genesis()` (asserts
`sha256d(header)` matches the expected hash with the correct byte order).

## Test vectors

- `verify_genesis()` returns the hash above; live mainnet chaindata
  height 0 stores exactly this hash.
