# GF-07: Transaction and script consensus subset (v2)

| Field | Value |
|-------|-------|
| BIP | GF-07 |
| Title | Transaction and script consensus subset (v2) |
| Author | Travis Dale Jones |
| Status | Active |
| Created | 2026-09-21 |

## Abstract

The v2 transaction layer: legacy Bitcoin transaction format with a
minimal script subset (data pushes, OP_0–OP_16, OP_CHECKSIG), P2PK and
OP_TRUE outputs, pure-Python secp256k1 with RFC 6979 deterministic
nonces and low-S enforcement, legacy SIGHASH_ALL, 100-block coinbase
maturity, and fee ≥ 0.

## Motivation

v1 blocks were coinbase-only. A live chain needs value transfer; the
subset keeps the consensus surface small enough to audit in one sitting
while covering the real use cases (P2PK payments, anyone-can-spend
faucets).

## Specification

1. **Transaction format**: legacy (non-segwit) serialization, as in
   Bitcoin.
2. **Script subset** (unknown opcodes fail closed):
   - data pushes (including PUSHDATA1, accepted as non-standard),
   - OP_0 (`0x00`), OP_1–OP_16 (`0x51`–`0x60`),
   - OP_CHECKSIG (`0xAC`).
3. **Standard output types**: P2PK (`0x21 <33-byte compressed pubkey>
   0xAC`) and OP_TRUE (`0x51`, anyone-can-spend).
4. **Input scripts**: `<64-byte signature><0x01>` (SIGHASH_ALL byte) for
   P2PK; empty for OP_TRUE.
5. **Signatures**: secp256k1 ECDSA, RFC 6979 deterministic nonces,
   low-S required, legacy SIGHASH_ALL sighash.
6. **Consensus tx rules** (checked per block, in `validate_block_txs`):
   - every input references an existing, unspent UTXO;
   - no double-spend within a block;
   - coinbase outputs mature after 100 blocks (`COINBASE_MATURITY`);
   - fee (inputs − outputs) ≥ 0;
   - all input scripts execute successfully;
   - coinbase value = subsidy + fees exactly.
7. **Mempool policy** (not consensus): fee-ordered admission, validated
   against UTXO + pending transactions, no RBF, persisted to
   `mempool.json`.

## Rationale

OP_CHECKSIG + P2PK covers real payments; OP_TRUE preserves the
anyone-can-spend coinbase tradition of the demo chain and funds the
faucet. Everything else is deferred to keep v2 reviewable.

## Reference implementation

`txscript.py`: script parser/interpreter, `validate_tx`,
`validate_block_txs`, `make_coinbase_v2`, sighash; `secp256k1.py`:
ECDSA sign/verify (cross-validated against coincurve in tests;
production never imports it); `mempool.py`: admission policy.

## Test vectors

- 15/15 adversarial consensus tests pass (`test_tx.py`): double-spend,
  immature coinbase spend, negative fee, bad signature, unknown opcode
  all rejected.
- Live testnet money loop demonstrated: faucet → send → confirm with
  exact balances.
